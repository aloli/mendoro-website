= Modifier le site — poste de travail Windows
:toc: macro
:toclevels: 2
:experimental:

Comment modifier les textes du site https://mendoro.fr[mendoro.fr], depuis un
ordinateur *Windows 10 ou 11 (64 bits)*.

toc::[]

== Avant tout : le compte GitHub

Les textes du site vivent sur https://github.com/aloli/mendoro-website[GitHub].
Il vous faut donc un compte, et une invitation à y écrire.

. Créez un compte sur https://github.com[github.com] si ce n'est pas déjà fait.
. Demandez à ALOLI de vous inviter sur le dépôt `aloli/mendoro-website`.
. Acceptez l'invitation reçue par courriel.
. Activez l'authentification à deux facteurs quand GitHub vous le proposera :
  elle est désormais obligatoire pour les comptes qui modifient du code.

== Deux façons de travailler

[cols="1,3a,2a"]
|===
| | Ce que vous pouvez faire | À installer

| *Dans le navigateur*
|
Corriger un texte, compléter les mentions légales, ajouter une prestation.
Vous voyez le rendu de votre texte directement sur GitHub.
|
Rien.

| *Sur votre ordinateur*
|
La même chose, mais confortablement : plusieurs fichiers ouverts,
recherche dans tout le site, travail hors connexion.
|
. Git
. Zed
|===

NOTE: Commencez par le navigateur. Pour corriger un paragraphe ou compléter une
rubrique, c'est suffisant — et il n'y a rien à installer ni à maintenir.

== A. Dans le navigateur

=== Modifier un texte

. Ouvrez https://github.com/aloli/mendoro-website/tree/production/content[le dossier `content`].
. Cliquez sur le fichier à modifier. **GitHub affiche l'AsciiDoc en rendu**,
  vous relisez donc votre texte mis en forme.
. Cliquez sur l'icône crayon (*Edit this file*), en haut à droite.
. Modifiez le texte. L'onglet *Preview* montre le rendu au fur et à mesure.
. En bas, décrivez votre modification puis cliquez sur *Commit changes*.

Le site est reconstruit et publié automatiquement. Comptez une à deux minutes.

[TIP]
====
Pour un travail plus long, tapez la touche kbd:[.] sur la page du dépôt :
un éditeur complet s'ouvre dans le navigateur, sans rien installer.
====

== B. Sur votre ordinateur

=== 1. Git

Git suit l'historique des modifications et les envoie vers GitHub.

. Téléchargez https://git-scm.com/download/win[Git pour Windows].
. Lancez l'installateur. Les options par défaut conviennent, **sauf une** :
 ** *Adjusting the name of the initial branch* → cochez
    `Override the default branch name for new repositories` et saisissez
    `production`, la branche utilisée par les dépôts ALOLI.
. Terminez l'installation.

Vérifiez dans un terminal (menu Démarrer → `Terminal`) :

[source,powershell]
----
git --version
----

NOTE: L'installateur propose de choisir un éditeur par défaut pour Git. Laissez
ce qui est proposé : vous n'en aurez pas besoin, car vos messages seront
toujours écrits directement dans la commande.

=== 2. Zed

L'éditeur dans lequel vous rédigerez les textes.

Téléchargez-le depuis https://zed.dev[zed.dev], ou en une commande :

[source,powershell]
----
winget install -e --id ZedIndustries.Zed
----

=== 3. L'extension AsciiDoc

Elle colorise les fichiers `.adoc` et rend leur structure lisible.

Le dépôt demande son installation automatiquement : à la première ouverture du
projet, Zed devrait s'en charger seul. Si ce n'est pas le cas, faites-le à la
main avec kbd:[Ctrl+Maj+X], en cherchant `AsciiDoc`.

[IMPORTANT]
====
Zed *colorise* l'AsciiDoc mais n'en affiche **pas le rendu**. Pour relire votre
texte mis en forme, deux possibilités :

* consultez le fichier sur GitHub, qui l'affiche en rendu ;
* ou publiez, et regardez le site — une publication ratée ne casse jamais le
  site existant.
====

=== 4. S'identifier auprès de GitHub

Dans un terminal, indiquez votre identité — elle apparaîtra dans l'historique :

[source,powershell]
----
git config --global user.name "Erik Pain"
git config --global user.email "votre.adresse@exemple.fr"
----

La première fois que vous enverrez des modifications, une fenêtre
*Git Credential Manager* s'ouvrira et vous proposera de vous connecter à GitHub
dans votre navigateur. Acceptez : vos identifiants sont mémorisés par Windows,
et vous n'aurez **aucun mot de passe ni jeton à manipuler**.

=== 5. Récupérer le site

[source,powershell]
----
cd $HOME\Documents
git clone https://github.com/aloli/mendoro-website.git
----

Ouvrez ensuite Zed, puis *File → Open Folder…* et choisissez le dossier
`mendoro-website`. Vous êtes prêt.

== Le cycle de travail

=== Récupérer les dernières modifications

Toujours commencer par là, pour partir de la version à jour :

[source,powershell]
----
cd $HOME\Documents\mendoro-website
git pull
----

=== Modifier un texte

Tous les textes du site sont dans le dossier `content\` :

[cols="2,3"]
|===
| Fichier | Contenu

| `content\site.adoc`
| Nom, fonction, domaine — repris sur toutes les pages

| `content\accueil.adoc`
| Titre et introduction de la page d'accueil

| `content\contact.adoc`
| Introduction du formulaire de contact

| `content\mentions-legales.adoc`
| Mentions légales, en entier

| `content\prestations\*.adoc`
| Une prestation par fichier, affichée dans l'ordre des noms de fichiers
|===

La syntaxe AsciiDoc utile ici tient en quelques règles :

[source,asciidoc]
----
= Titre de la carte               <1>

Un paragraphe ordinaire.          <2>

Un second paragraphe : *gras*, _italique_.

* premier élément de liste        <3>
* second élément

https://exemple.fr[texte du lien] <4>

[.todo]#texte à compléter#        <5>
----
<1> Première ligne du fichier : elle donne le titre affiché.
<2> Les paragraphes sont séparés par une ligne vide.
<3> Une liste à puces.
<4> Un lien.
<5> Un passage surligné en attente de contenu, visible sur le site.

[TIP]
====
Pour *ajouter une prestation*, créez un fichier dans `content\prestations\`,
nommé avec un numéro d'ordre : `09-ma-nouvelle-prestation.adoc`. Elle
apparaîtra sur la page d'accueil **et** dans la liste déroulante du formulaire
de contact, sans autre manipulation.

Pour *retirer* une prestation, supprimez son fichier.
====

=== Publier

[source,powershell]
----
git add .
git commit -m "Description de votre modification"
git push
----

GitHub reconstruit alors le site et le publie. Comptez une à deux minutes. Vous
pouvez suivre l'avancement sur
https://github.com/aloli/mendoro-website/actions[la page Actions du dépôt] :
pastille verte, c'est publié ; pastille rouge, il y a un problème.

[WARNING]
====
Le message de `commit` est obligatoire et décrit ce que vous avez changé. Il
reste visible dans l'historique : soyez explicite, par exemple
`Ajout de la rubrique Ma carrière` plutôt que `màj`.
====

== Réglages de confort (facultatif)

Les textes sont écrits en lignes longues. Pour que Zed les replie à l'écran,
ouvrez la palette de commandes avec kbd:[Ctrl+Maj+P], cherchez
`open settings`, et ajoutez :

[source,json]
----
{
  "soft_wrap": "bounded",
  "preferred_line_length": 90
}
----

== En cas de problème

[cols="2,3a"]
|===
| Symptôme | Que faire

| `git` n'est pas reconnu comme une commande
| Le terminal a été ouvert avant l'installation de Git. Fermez-le et
  rouvrez-en un.

| `git push` est refusé (`rejected`)
| Quelqu'un a modifié le site entre-temps. Lancez `git pull`, résolvez les
  éventuels conflits, puis `git push` à nouveau.

| La pastille est rouge sur la page Actions
| Cliquez dessus pour lire le journal : il indique la ligne fautive, le plus
  souvent une erreur de syntaxe AsciiDoc. En attendant, le site précédent
  reste en ligne — une publication ratée ne casse jamais le site existant.

| Le site en ligne n'a pas changé
| Votre navigateur affiche une version en cache. Rechargez avec kbd:[Ctrl+F5].

| Les fichiers `.adoc` ne sont pas colorisés
| L'extension AsciiDoc n'est pas installée. Voir l'étape 3.
|===

Pour toute autre difficulté, ouvrez un ticket sur
https://github.com/aloli/mendoro-website/issues[la page Issues du dépôt].

== Annexe — reconstruire le site sur votre machine

Vous n'en avez normalement **pas besoin** : GitHub reconstruit le site à chaque
publication, et vous relisez vos textes sur GitHub avant de publier.

Cette annexe ne concerne que le cas où vous voudriez voir le site entièrement
mis en page, avec ses couleurs et sa disposition, sans publier. Il faut alors
installer une chaîne de compilation complète — Build Tools de Microsoft et
Crystal, plusieurs gigaoctets — ou obtenir d'ALOLI un exécutable déjà compilé.

Dans les deux cas, demandez à ALOLI : c'est une installation à faire
accompagné, pas seul.
